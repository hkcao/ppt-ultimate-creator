# 终极ppt生成

交付原生可编辑 `.pptx`。优先级：内容准确 > 语义结构与编辑性 > 视觉还原；允许少量视觉差异，但须逐页说明。

## 关键约束

- **事实有据**：文字、数值、关系与来源以 `slides.yaml` 为准，实验结果和结论须定位到实际读到的原文。原图可保留、重标注或基于核实数据重绘；缺数据时保留原曲线并解释，不从像素估数或用 AI 补造结果。图片/OCR 不反向定义事实。
- **模板落地**：有对应 PPTX/POTX 时，必须加载其项目副本，沿用母版、主题、版式和固定项，不能从空白 PPT 仿制。内置模板位于本技能 `assets/templates/defaults/`；用户模板在外部库，原件不修改。工具不兼容时寻找替代实现，不能擅自降级。
- **真正可编辑**：正文、图形、图表、表格用原生对象；公式必须以“插入公式”方式生成 OMML 等原生数学对象，不能用普通文本、Unicode 拼式或图片代替。一个语义元素避免碎片拼接。照片、原文截图和复杂插画可作为独立图片，说明其内部不可编辑；禁止整页 AI 图覆盖正文冒充可编辑 PPT。
- **字体与能力**：默认中文微软雅黑（Microsoft YaHei）、英文 Times New Roman；公式用数学字体，明确的用户/品牌要求优先。检查实际字体，替代时说明影响。优先当前模型/宿主已有能力，识别、生成、编辑分别核实；不强制 GPT、Codex 或 OpenAI API。仅按需读取 [外部生图](references/image-backend.md)。
- **真实验证**：先核实生图、PPTX 构建与渲染能力。视觉稿必须是真实 AI 图像结果；最终必须渲染 PPTX 并检查内容、视觉和编辑结构。能力缺失时保留成果并说明未完成阶段，不能以 HTML 截图、结构统计或未执行操作冒充验证。

## 确认与续做

默认只等待 3 次：**启动理解与需求 → 大纲＋低保真蓝图 → 代表性 AI 样张**。六阶段不等于六次等待；样张确认后自动扩展全套、重建和校验。

使用当前可用的 ask 工具并遵循其模式限制；没有工具或返回空值时，普通提问并结束本轮，状态记 `waiting_for_user`。必要答复到达前只做不依赖答案的资料核实，不写大纲/布局或推进下一阶段。沉默、超时、初始“帮我制作”均不算后续批准。无法暂停的无人值守宿主只能交付待确认摘要，除非用户明确免交互。

在 `state.json` 记录产物版本与用户原话。已有有效批准或用户明确跳过的节点不重复等待；已知字段不重复问，信息齐备的新项目仍需启动确认。自动扩展页记 `generated_reference`，不能冒称逐页批准。重大内容/风格偏离、证据缺口或编辑性取舍才集中提问；普通修复不新增确认。用户指定详细确认节奏时遵循。

尊重用户输出目录，否则创建独立项目目录。续做先读 `state.json`、`brief.md`、`slides.yaml` 和确认记录，只改受影响页；记录结构及批准失效规则见 [交互与项目记录](references/planning.md)。

## 六阶段流程

### 1. 阅读来源，完成启动确认

只读用户指定范围：目录先列清单；论文/文档记录页码与图表号；网页实际读取并记录链接和访问日期。区分内容来源与样式参考，列明无法读取、冲突与证据缺口，不凭标题/摘要猜全文。提取证据时按需读 [证据与执行](references/execution.md)。

先理解关键原理、因果关系和证据，再简述理解并合并询问呈现范围/深度、受众/目的及是否有参考模板、已有 PPT 或风格图。已有明确模板直接沿用；用户没有或委托推荐时再给少量建议，不额外开模板确认轮。收到启动答复后进入阶段 2。

### 2. 需求、模板与大纲

读取 [项目记录](references/planning.md)、[模板库](references/templates.md) 和 [设计方法](references/design-methods.md) 的类别索引，只加载选中类别。用户给逐页内容时保留意图并补齐缺口；只给资料时根据确认需求起草，允许混合。

在 brief 明确范围、主线、受众、目的、观看方式、深度、时长、页数（含封面）、比例、语言、风格、保留/排除内容和编辑要求。次要样式可用默认值并展示，实验事实不可默认补齐。工作汇报无指定模板时采用华为风格与内置浅色 16:9 模板；其他类别不自动套用。

逐页在 `slides.yaml` 记录标题、核心信息、正文/证据、图表关系、布局和素材；一页一个主要沟通任务，不强造结论标题。不单独等待大纲批准，继续阶段 3。

### 3. 低保真蓝图，合并确认

按 [低保真规范](references/ppt-lofi-authoring.md) 从规格整理 `preview/lofi.md`：每页包含真实关键内容、ASCII 区域草图和自然语言视觉指引，标明比例、阅读顺序、内容类型、关系与素材位置；有模板时注明版式及固定区。可用 `scripts/storyboard.py` 批量整理，脚本不代替布局设计。

此阶段只解决内容与空间组织，不做精细 HTML/CSS 或装饰图片。共享样式引用 brief，不逐页重写。展示完整蓝图及页序总览，检查主线、密度、布局节奏和证据；修改回写规格，合并确认大纲与蓝图版本。

### 4. AI 样张与全套视觉稿

用确认的蓝图、规格、共享风格和实际模板参考生成一张代表性内容样张，封面不是默认样张。有模板时先渲染选用版式供参考，只在允许的内容区内设计。Logo、截图等精确素材最终沿用原件；生图不构成新证据。

样张涉及复杂原生图表、连接关系、字体或公式时，先按 [原生对象与验收](references/editability-and-qa.md) 做局部可编辑实现与实际渲染；含公式须验证复杂公式的插入、保存和显示。不可实现的效果在此阶段处理，不等全套完成后才暴露。

样张确认后生成其余页，沿用样式并按页面角色变化布局。保存逐页提示词、素材、实际模型/工具、输出路径与版本；主 agent 核对规格和样张，提供全套查看入口，通过后冻结为生成参考版本并自动继续。不能重生成参考图来掩盖 PPT 差异。

### 5. 构建原生可编辑 PPT

读取 [原生对象与验收](references/editability-and-qa.md)。使用环境已有的依赖发现、构建和渲染工具；如有适用的 presentations 技能，按需读其实现说明。输入为确认规格、蓝图、模板文件及冻结图片，原生对象与数据以规格为准，图片指导视觉。

多页独立任务按 [证据与执行](references/execution.md) 并行，少量简单页无需强拆。subagent 使用 `fork_turns="none"` 或等效无历史模式，只给相关页、证据和共享约束；主 agent 负责确认、模板构建入口与最终组装。数据折线用原生图表，折线路径优先单个连接符/自由曲线，不用多线段拼接。

### 6. 渲染、对比与交付

实际渲染最终 PPTX，逐页对照规格与冻结图片，按验收文档检查内容、原生结构、字体/公式及画布和容器边界。先修事实与编辑性，再调视觉；程序检查和目视检查互不替代。不能只查画布而漏掉卡片内溢出。

生图或 PPT 同一问题默认最多两轮自动修复；重大差异仍在或无进展时展示页面、证据和选项，用户新反馈后可继续。结构问题回到对应页蓝图调整，不无限重生成。事实错误、缺页、关键关系错误或未满足原生编辑要求不能算完成。

交付 `.pptx`、使用说明及逐页残留差异/图片编辑边界。保留蓝图、规格、确认记录、生成代码与 QA 记录供续改，不默认把临时文件全贴给用户。仅实际在 PowerPoint 检查过才声称已在该软件验证。

## 参考加载原则

按当前阶段读取已链接的文档，细节以对应专题维护；同一任务内未变化的文档不重复加载。不预读全部风格、模板或后端资料；华为风格保留全文，选用时读取。worker 只拿所需片段，主 agent 不省略必要证据核实。
