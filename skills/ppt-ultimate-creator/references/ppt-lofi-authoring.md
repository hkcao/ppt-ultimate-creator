# 低保真蓝图制作规范

阶段 3 使用 Markdown + ASCII 表达内容与空间组织，替代 HTML 页面制作；阶段 4 才生成高保真 AI 视觉稿。蓝图既供用户审阅，也供生图执行器理解布局，不能只是标题列表。

## 先分析，再分页

从已核实内容中识别核心板块、数据证据、因果/流程关系和总分层级，围绕每页的主要沟通任务分配页面类型：封面、总览、详情、方法、路线图、对比、总结。按受众、讲述时长和已确认的内容取舍控制页数；需要全保留时可移至附录或拆页，不靠无限缩小文字硬塞。页面类型参考当前类别文档，不给所有类别统一套华为布局。

内容与大纲在同一份蓝图中确认，不先等一次大纲批准再单独等蓝图批准。初始需求未确认时，不提前编写逐页稿。

## 文件与内容真值

`slides.yaml` 保存逐页内容真值及布局字段；`preview/lofi.md` 是由它整理生成的审阅视图。只改蓝图而未回写规格会造成后续生图/PPT 内容漂移。改动回写后生成新版本，并在 state 中记录用户确认的版本。

文件包含：

- 全局摘要：主题、受众、风格文档/共享 design_tokens、比例、页数、密度与内容取舍原则。
- 模板依据：实际模板路径与哈希、选用版式/母版、参考页、固定区域和可编辑内容区。只有视觉参考时明确标注。
- 每页一个 section：稳定 ID、标题、核心信息、真实文字/数据及来源、ASCII 蓝图、视觉指引、素材和编辑性要求。
- 末尾的生图总指引：共享风格引用、模板约束、比例、密度、每页一张独立图及逐页生成清单。

可将当前规格转为 JSON 后运行 `scripts/storyboard.py slides.json preview/v2/` 批量整理 Markdown。脚本只负责序列化，不推理布局；每页需先填写 `blueprint` 和 `visual_guidance`。无须再制作同内容的 HTML 或一整套线框图片。

## ASCII 蓝图

用 `┌ ┐ └ ┘ │ ─` 画区域，箭头表达方向，缩进表达层级，分隔线表达分栏。草图宽度大致反映占比，同时用文字注明准确相对比例；中文字符对齐不是像素坐标验收。画清标题、主体、注释与模板固定区，不能只有方框名而没有内部信息组织。

每个面板标明内容类型和用途：

| 标签 | 必须表达的内容 |
| --- | --- |
| `[文字]` | 实际要点、层级、需突出的短句 |
| `[数据]` | 指标、真实数值、单位、比较基期及来源 |
| `[图表]` | 图型、系列、轴/单位、关键对比及来源数据或原图 ID |
| `[表格]` | 行列含义、需保留的数据及高亮位置 |
| `[流程]` | 节点、方向、分组、输入与输出 |
| `[实拍]` | 用户/来源实际素材 ID、裁剪意图，不虚构照片 |
| `[概念图]` | 主体、风格、氛围、视角及参考，明确属于概念表达 |
| `[公式]` | 核实的数学源表达、符号说明与位置；成品必须插入原生公式对象 |

原始实验图可占位，但必须有明确来源和使用策略（原图、重标注或有真实数据的重绘）。只写“这里画漂亮的实验结果”不够。ASCII 中可用素材 ID 和短标签，完整文字、数值、公式在同页规格中保留，不要求把长正文塞进字符框。

## 单页示例

以下是无实验数据的方案研讨布局示例；具体事实必须替换为当前来源，不能把示例当结论：

````markdown
## P3 / s03：方案对比与待决策项

核心信息：按已确认的约束比较方案，集中呈现待核实条件。
模板版式：本次选定模板的标题+内容版式；固定页眉页脚保持。
布局：主体左 40% 放约束，右 60% 放比较表；底部保留来源。

```text
┌────────────────────────────────────────────────────┐
│ 标题区域（沿用模板）                                 │
├────────────────────┬───────────────────────────────┤
│ [文字] 选择约束     │ [表格] 方案 A / 方案 B          │
│ 1. 已确认要求      │ 按相同维度比较，不预填优胜者    │
│ 2. 待核实条件      │ 证据不足的单元格明确待核实      │
├────────────────────┴───────────────────────────────┤
│ [文字] 待决策项及来源                固定页脚区域   │
└────────────────────────────────────────────────────┘
```

**视觉指引**：
- 页面类型：方案对比；阅读顺序为约束 → 对比 → 待决策项。
- 共享样式：引用 brief.design_tokens 与选中类别的对比页建议。
- 重点：只高亮决定取舍的差异，不给全部单元格加色。
- 素材/编辑：表格与文字原生可编辑；来源位置不可被裁掉。
````

## 视觉指引与模板约束

每页在草图后写自然语言视觉指引：页面类型、区域比例、第一焦点、阅读顺序、数据高亮、图例/公式位置、素材 ID 与必要装饰。引用共享风格参数名，不逐页复制所有色值和字号，不写 CSS。需要偏离共享样式时说明该页理由，不能随机发明配色。

有 PPTX/POTX 模板时先实际检查版式并渲染参考页，蓝图标出模板内容安全区。高保真图只细化该区域；页眉、页脚、Logo 和固定背景遵循已确认模板约束。布局需求不适配现成版式时，在原母版下设计内容区，不能借机抛弃模板。模板原文件如何用于构建和验收见 [模板库](templates.md)。

蓝图阶段不做纹理、阴影、渐变、精细插画、像素级对齐或装饰试错；这些由样张承接。蓝图可以引用已确认风格，但不冒称精细视觉已确认。

## 生图总指引与交接

末尾统一列出选用风格、模板、画幅、密度原则，以及每页 ID、标题、类型和主要视觉元素。生图执行器用已确认蓝图和真实内容清单逐页生成，一页一张独立图片，不把全套拼图裁成页面。输出到 `visuals/`，保留提示词、参考素材、实际工具与版本。

先生成代表性内容样张，用户确认后再扩展其余页，不新增一轮全套图批准。使用当前模型或宿主真实可用的生成能力，外部 API 仅为可选后端；不得用 HTML/SVG 手工截图替代 AI 高保真稿。工具选择遵循技能的平台无关能力规则。

主 agent 掌握整套蓝图；独立页 worker 只拿该页蓝图/规格片段、必要证据/素材、模板版式参考、短版共享规范和输出路径。文件路径要精确到页/段，不让每个 worker 打开完整蓝图或全部风格资料。

## 质量检查与返工

交给生图前逐页检查：主要沟通任务清楚；区域占比与信息量匹配；关系和阅读顺序明确；关键文字、数字、单位、公式、引用均可核对；原图/重绘方式明确；模板固定区不被占用。3–6 个核心信息组可作为密度参考，实际以可读性和内容完整性判断，不作为硬配额。

只有标题列表、等大空框、未指明图例/来源的占位或大段原文都需先补足信息设计。无法容纳内容时调整组织或拆页，不把结构问题推给生图模型猜。完整蓝图审核只确认内容与区域布局，不能替代高保真样张确认或最终 PPT 实际渲染。

生图后按规格核对文字、数值和关系；乱码/事实偏差需修正，AI 图片不能成为新数据来源。连续两次仍无法修好区域比例或信息承载问题，回到该页蓝图调整，按主流程处理确认失效范围。
