# 原文证据、脚本与多页并行

## 证据优先

先检查原文的关键原理、实验设置、比较基线与结论边界，仅在未明确时向用户核对想讲哪些机制、哪些结果以及多深。内容已给出也不等于范围和技术深度已经确认。

实验图表按可读性选择原图、重标注或重绘，截图不是绝对要求：PDF 可裁剪页面区域保留矢量标注的渲染；网页可提取原始图片或截图；Office 可提取媒体，表格必要时截取实际渲染。保留标题、坐标、图例、单位与影响理解的注释，不把整篇资料截成背景。素材哈希、位置和引用写入 sources.md/素材清单。

AI 高保真稿可以预留原图位置或引用原图，最终 PPT 使用原始素材或经数据核对的确定性重绘，不能使用 AI 自由生成的实验曲线、数值或表格。缺失原文数据则保留原图；要求数据可编辑时说明缺口并请用户选择提供数据或接受图片。正文、标题及讲解图形仍原生可编辑。

## 可重复步骤交给脚本

先用环境依赖发现工具，复用现有生成/渲染工具，不为每页重新搭建环境。随技能提供：

- `scripts/extract_pdf.py`：按指定页/裁剪框批量导出 PDF 图片与文字，记录源哈希、页码和坐标。需要 PyMuPDF。适合先看页级预览、再选具体图表裁剪，避免逐页模型抄录。
- `scripts/storyboard.py`：从需求明确后起草的 JSON 内容规格生成整套低保真 HTML，转义文本、应用统一画幅和字体。它只替代重复 HTML 编码，不替代模型决定叙事/布局，也不产生 AI 视觉稿。

两者 `--help` 给出用法。输出目录要求为空，防止覆盖确认稿；修改时指定新版本目录。提取脚本不能自动判断原理、图表语义或 OCR 扫描件；无文字不等于无内容。

生成阶段复用一份 PPT 构建入口，按页模块导出原生对象；数据填充、尺寸换算、文件哈希、渲染、缩略总览和 OOXML 结构统计批量执行已有工具/项目脚本。不要反复让模型复制数值、重新读未变化的全文或重写相同布局代码。图表准确性、裁剪语义、审美判断仍要检查。

记录阶段耗时、页数、缓存命中与实际可取得的用量；没有对照测量不声称加速倍数或 token 减少。subagent 可能增加总 token，主要收益是降低独立页面的等待时间。

## 多页 subagent

本技能默认采用适合任务规模的多页并行，无需另加批准关卡；用户要求串行时遵循。按主流程的合并预览与样张确认节点，对同阶段的独立页面分工。通常使用 2–4 个 worker，受实际并发额度和生图工具限制；工具不允许并发时只并行素材准备或页模块编码。少页/简单页无需强行拆分。

主 agent 负责理解原理、用户交互、整套主线、事实与风格基线。创建 subagent 时明确 `fork_turns="none"`（或当前工具等效的无历史选项），不使用默认继承或全历史 fork。worker 只接收分配页的规格、必要原文片段/素材、共享设计规范、已确认样张和明确输出目录，避免复制整段历史。明确中文/英文字体与原文证据规则。

每个 worker 仅写自己的页目录，返回文件路径、引用定位、检查结果和缺口；不能改共享 brief/state、代用户批准、擅自跨阶段或重写别页。主 agent 验证引用和版本，再用共享构建入口组装；避免直接拼接多个独立 PPTX 导致母版、关系和字体漂移。

样张确认前不并行铺开全套生图。修改只重新派发受影响页面；超限/失败减少并发并保留成功产物。最终统一检查页序、跨页重复/矛盾、字体、图表证据和实际渲染。依赖最终组装的验证不可提前声称完成。

## 控制上下文与重复工作

- 主 agent 提供每个 worker 的最小任务包：页 ID/版本、此页在整套中的作用、前后页各一句衔接、页规格与证据文件路径、短版共享样式和构建接口、样张路径、输出目录及验收条件。明确禁止读取全套聊天或无关页；信息不足时返回具体缺口。
- 不给每个 worker 完整 SKILL.md、整篇论文、全套图片或整个 slides.yaml；只给适用约束与精确片段。文件路径不是免 token，要求 worker 仅打开所需页/行/区域。必要原始证据不能因节省 token 而省略。
- 相似简单页每 worker 处理 2–3 页，复杂页独立处理；纯 API 请求/裁剪/渲染用批量脚本或工具并发，不为等待网络请求启动 agent。局部返修给原 worker 仅发送差异与新版本，不重发整个包。
- 主 agent 先查状态与文件哈希，只重读变更资料；长文先索引后定点提取。保持一份内容真值，brief 只放整套要求，不再复制所有逐页正文。
- 模板发现先看索引再看候选；设计、模板、后端参考按需读取，不让每页重复加载。worker 返回路径、状态和差异摘要，不回传全部 HTML、base64、原始日志。
- 生成缓存须匹配页规格、样式、源素材、模型与参数的哈希；参数或上游证据变化后失效。现有脚本不实现自动缓存编排，由项目构建入口记录和检查，不声称缓存已命中。

## 图例简化与数值保真

原图图例简略时，在图边加“原缩写 → 直白含义”或直接标注系列，先解决理解问题。布局仍难读且有原始数据、精确数值表或作者代码时，用原生图表重绘。逐系列核对坐标、数值、单位、误差条、轴刻度（含对数轴）、实验条件和基线；保存数据来源与重绘映射。不得用折线形状的像素高度估算原实验数据。

仅有原图且无法精确恢复数据时，保留原曲线并放大/增加图例说明；不把重画的示意趋势当成实验结果。机制图可按原理重绘，不需要沿用论文的抽象符号布局，但节点、方向和含义必须一致。

## 生图交接与结构返工

每张最终参考图对应一页和锁定画幅；可并发逐页请求，不能把全套拼成一张图再裁切冒充逐页稿。拼图仅用于浏览。按规格中的可见文字清单核对标题、数字、单位和来源，视觉能力或 OCR 可辅助，不能用 OCR 结果反向覆盖内容真值。

连续两次修复仍有区域比例、层级或承载过量问题时，回到该页内容/HTML 重排，不继续堆叠提示词修补坏布局。只有影响已确认内容或整体风格时重新请用户决策，纯还原修复自行完成。
