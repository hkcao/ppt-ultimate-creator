# 原文证据、脚本与多页并行

## 证据优先

先检查原文的关键原理、实验设置、比较基线与结论边界，向用户核对想讲哪些机制、哪些结果以及多深。内容已给出也不等于范围和技术深度已经确认。

实验图表优先沿用原文：PDF 可裁剪页面区域保留矢量标注的渲染；网页可提取原始图片或截图；Office 可提取媒体，表格必要时截取实际渲染。保留标题、坐标、图例、单位与影响理解的注释，不把整篇资料截成背景。素材哈希、位置和引用写入 sources.md/素材清单。

AI 高保真稿可以预留原图位置或引用原图，但最终 PPT 必须嵌回原始素材，不能使用 AI 重绘的实验曲线、数值或表格。缺失原文数据则保留原图；要求数据可编辑时说明缺口并请用户选择提供数据或接受图片。正文、标题及讲解图形仍原生可编辑。

## 可重复步骤交给脚本

先用环境依赖发现工具，复用现有生成/渲染工具，不为每页重新搭建环境。随技能提供：

- `scripts/extract_pdf.py`：按指定页/裁剪框批量导出 PDF 图片与文字，记录源哈希、页码和坐标。需要 PyMuPDF。适合先看页级预览、再选具体图表裁剪，避免逐页模型抄录。
- `scripts/storyboard.py`：从确认后的 JSON 内容规格生成整套低保真 HTML，转义文本、应用统一画幅和字体。它只替代重复 HTML 编码，不替代模型决定叙事/布局，也不产生 AI 视觉稿。

两者 `--help` 给出用法。输出目录要求为空，防止覆盖确认稿；修改时指定新版本目录。提取脚本不能自动判断原理、图表语义或 OCR 扫描件；无文字不等于无内容。

生成阶段复用一份 PPT 构建入口，按页模块导出原生对象；数据填充、尺寸换算、文件哈希、渲染、缩略总览和 OOXML 结构统计批量执行已有工具/项目脚本。不要反复让模型复制数值、重新读未变化的全文或重写相同布局代码。图表准确性、裁剪语义、审美判断仍要检查。

记录阶段耗时、页数、缓存命中与实际可取得的用量；没有对照测量不声称加速倍数或 token 减少。subagent 可能增加总 token，主要收益是降低独立页面的等待时间。

## 多页 subagent

本技能默认采用适合任务规模的多页并行，无需另加批准关卡；用户要求串行时遵循。在范围/大纲/HTML 及代表性样张相应确认后，对同阶段的独立页面分工。通常使用 2–4 个 worker，受实际并发额度和生图工具限制；工具不允许并发时只并行素材准备或页模块编码。少页/简单页无需强行拆分。

主 agent 负责理解原理、用户交互、整套主线、事实与风格基线。worker 只接收分配页的规格、必要原文片段/素材、共享设计规范、已确认样张和明确输出目录，避免复制整段历史。明确中文/英文字体与原文证据规则。

每个 worker 仅写自己的页目录，返回文件路径、引用定位、检查结果和缺口；不能改共享 brief/state、代用户批准、擅自跨阶段或重写别页。主 agent 验证引用和版本，再用共享构建入口组装；避免直接拼接多个独立 PPTX 导致母版、关系和字体漂移。

样张确认前不并行铺开全套生图。修改只重新派发受影响页面；超限/失败减少并发并保留成功产物。最终统一检查页序、跨页重复/矛盾、字体、图表证据和实际渲染。依赖最终组装的验证不可提前声称完成。
