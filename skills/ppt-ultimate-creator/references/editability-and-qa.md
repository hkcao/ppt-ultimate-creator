# 原生对象与对比验收

## 对象选择

先表达语义，再考虑外观相似度；对象少并非独立目标。需要分别改动的节点保持独立，一个语义元素也不要碎片化。

| 内容 | 实现与检查 |
| --- | --- |
| 标题、正文、标签 | 原生文本框，按段落/语义分块，合理换行；不用逐字对象、文字描边路径或嵌字图片代替正文。 |
| 需要重建且原始数据已核实的数据折线、柱状、饼图 | 原生图表及可编辑数据，保留类别、系列、数值、单位、图例。不支持时提出取舍，不能把截图称为可编辑图表。 |
| 折线箭头、流程连接 | 优先单个原生连接符，必要时一个自由曲线/自定义几何对象；可连接节点时保留连接关系。不以多个线段加三角形模拟单个箭头。 |
| 需要重建的表格 | 原生表格，保留单元格及结构，不为每条边框建独立线段。 |
| 流程节点、架构框 | 原生形状、独立标签及必要连接；合理组合，但组合碎片不等于语义对象。 |
| 照片、截图、复杂插画 | 独立可移动/缩放/替换图片，明确内部不可编辑。 |
| Logo、论文原图、原文实验图表 | 可使用原图或基于核实数据重绘；原图保留图例、单位、必要条件和引用，明确图内不可编辑；需改图内数据/路径时确认重建范围，移动图片不等于编辑内部。 |

嵌入的 SVG 可能仍是图片对象，不能以“导出 SVG”证明原生可编辑。不得用整页确认图覆盖底下对象通过视觉比较。纯背景照片可做背景，但正文、图表、标签和编辑结构必须真实存在且可见。

## 生成前

检查当前库是否支持所需原生对象/数据编辑，优先环境已有工具，不编造 API。复杂页先验证小范围原生实现，再铺开全套。

有对应 PPTX/POTX 模板时，先验证构建入口实际加载项目模板副本及母版/版式映射，按 [模板库](templates.md) 检查结构继承。图片与模板固定项冲突时纠正图片设计，不擅自丢弃模板。

精确文字、数据、关系从 slides.yaml 传入生成代码；图片用于位置、间距、配色。源内容与确认图矛盾时纠正事实，说明或重新确认重大视觉变化。

## 三类验证

目视检查和图表理解优先使用当前模型或宿主已有视觉能力，无需另行调用 GPT 识别。缺少视觉输入能力时才寻找可用替代；OCR 或结构统计不能独立证明版式质量。

### 内容

- 页数/顺序、标题、正文、数字、单位、图例和引用对照规格。
- 图表数据逐项核对原文定位，不按图片高度猜数字。原图对照原始页面检查裁剪没有遗漏坐标、单位、图例或限定条件；提取的图片可能缺少 PDF 矢量标注，必须目视核对。
- 流程/架构节点、边、方向、分组、层级准确。
- 提取 PPTX 文字并核对，再结合渲染排除“存在但被遮挡”。

### 编辑结构

- 检查文字、图表、表格、形状、连接符、图片的真实类型；必要时解包检查 OOXML 和图表数据部件。
- 原生对象清单对照逐页要求；数量只能定位异常，不能独立证明可编辑。
- 查找小线段/文本碎片、整页图片覆盖、缺失原生数据、不合理组合。
- 验证包可读、关系目标完整、媒体/字体依赖可用；有模板时核对实际使用的母版、版式、主题及固定元素，而非仅检查未使用的模板部件是否存在。程序检查不等于在 PowerPoint 中实际交互编辑。

### 视觉

- 使用 PPTX 渲染器/演示软件导出实际页面，与冻结图片统一比例后并排查看；不使用低保真蓝图或 AI 参考图冒充 PPT 渲染证据。
- 逐页检查字体层级、配色、对齐、留白、位置、线条、裁剪、重叠、溢出和遮挡；缩略总览只辅助全套一致性。
- 可用叠加/像素差异图定位，不以未经验证的相似度百分比作为通过依据；抗锯齿差异不应压倒内容和编辑性。
- 默认中文 Microsoft YaHei、英文 Times New Roman，检查混排 run 及渲染实际字体。字体替代引起换行/布局变化时调整后再渲染，不默默换掉指定品牌字体。

## 修复与报告

逐页记录参考版本、PPT版本/渲染图、三类检查结果、修复动作和残留影响。固定参考图不变，修 PPT 后重新检查受影响页及公共样式影响页；最终组装后检查页数和包完整性。

事实/单位错误、缺内容、方向错误、遮挡不可读、关键要求不可编辑为重大问题。未解决只能交付明确未完成的草稿及原因。

允许的小差异包括装饰渐变简化、非关键阴影/圆角差异或抗锯齿差异。必须基于实际观察，按页说明，不空泛声称“基本一致”。

无 PPTX 渲染工具时保留文件与结构检查结果，报告“视觉校验未完成”，不得宣称验收完成。重复修复失败按主流程停止自动重试，展示取舍供用户决定。

## 公式与符号专项检查

- 公式源记录规范数学表达和出处；必须插入 OMML 等可编辑原生公式对象，含分式、上下标、矩阵、求和、约束和独立等式。正文中的普通术语/变量名称无需逐字变成公式，但不得将一整条公式伪装成普通标签。禁止用 Unicode 拼式、普通上下标文本或未解析 LaTeX 代替公式对象。
- 公式字体独立于中文/英文字体，检查实际字形覆盖与目标渲染器。重点检查上下取整、求和上下限、希腊字母、等价/不等号、上下标及括号层次。避免用外观类似但语义不同的字符替代。
- 若生成环境不能保留可编辑公式，先寻找支持的生成/插入路径；仍不可用则明确未完成，不能默认以公式图片交付。只有用户明确批准该项降级后才能用图片，并保留源表达、标注不可编辑。
- 最复杂公式页先实际渲染并放大查看；对照原文逐项核对。XML 文本存在、无替换字符或文件能打开都不能证明没有乱码。正文缺字与公式缺字分别定位；单一渲染环境的字体问题不能直接归因于原文件或某 Agent。
- 维护需公式对象的页/位置清单，对照最终 PPTX 的数学部件（如 a14:m 与 m:oMath/等价原生结构）核对全套覆盖及分式、上下标、矩阵结构；单个公式存在或使用数学字体不代表合格。原生结构检查不等于已在 PowerPoint 中交互编辑。

## 边界、容器与布局验收

生成代码保留内容块与所属容器的对应关系，按容器内边距布置子元素。布局检测分别覆盖幻灯片边界、卡片/分栏/图表绘图区边界、页眉页脚安全区；计入分组变换、旋转、箭头头部和实际文本边界。几何框合法也可能文字溢出，必须结合渲染复核。

故意跨容器的连线仅在关系需要且不遮挡时允许，记录为有意设计；普通节点、图例和成本标签不得挂到卡片外。越界时优先简化结构、调整网格或拆分表达，再缩减次要文字；不要整体缩字至难读或扩大外框掩盖问题。

最终组装后重跑受公共样式影响的页面检查，并看整套缩略图与正常尺寸的复杂页。含占位汇报人、未完成日期、残留 LaTeX、非必要中英夹杂、错误数量标题的页面不算定稿。自动检测是定位线索，需逐条判断，不能用“无越出画布”代替完整视觉验收。
