# 交互与项目记录

## 收集信息

先理解资料：用简短摘要说明关键原理、因果关系、证据与局限，区分原文陈述和自己的推断。关键需求缺失时实际发起一次合并的 ask 类澄清，优先询问呈现范围、深度、受众和目的，给少量可选方向。将“是否有希望参考的模板/已有 PPT/风格图”合并到这次询问；有则沿用，无或委托推荐时才给建议，不额外开一轮风格问答。必要回答到达前不创建 slides.yaml、不写逐页标题或布局；可读资料、提取原图和记录未知项。不要把“我会先澄清”当成已经完成交互。

整份 brief 包含：主题、范围、受众、目的、现场讲述或自主阅读、整套主线、技术深度、时长、总页数及封面计数、语言、比例、风格/模板、品牌固定项、必须保留/排除内容、特殊编辑要求、中文字体 Microsoft YaHei、英文字体 Times New Roman 与实际替代情况。比例未知可提议 16:9，在大纲确认时明确假设。现场讲述页由备注承载口述细节；自主阅读页应保留足够上下文，不能机械删成口号。

逐页表包含：页码/稳定 ID、初步标题、核心信息、内容与证据、呈现方式、大布局、素材、编辑要求。依据不足时使用中性主题标题，不强造结论。

模式 A 可以建议：“直接发每页标题、要点及期望的图表/布局；没有完整大纲也没关系，我会补齐建议。”模式 B 有关键缺口时先给需求选择及推荐理由，必要回答到达并确定 brief 后起草大纲和 HTML，合并展示确认；不要要求用户替你完成方案。两者都沿用已有受众/目的等条件。

一次只处理当前阶段最有影响的少量问题。确认问题指向可审阅产物的版本和决策，不泛问“满意吗”。异步询问工具可用时使用，必要答案到达后再推进依赖阶段。默认确认节奏以 SKILL.md 为准，不逐页重复询问同一风格或为已知需求再设置批准。

## 项目文件

文件到需要时再生成，不批量创建空占位文件：

```text
<project>/
  brief.md               # 整份需求、模板约束
  sources.md             # 来源定位、依据、缺失/冲突
  slides.yaml            # 逐页内容的结构化真值
  state.json             # 阶段、版本、确认、待办
  preview/deck.html      # HTML 草稿
  visuals/               # AI 原图和版本
  prompts/               # 每页提示词及参考记录
  assets/                # 使用的源素材副本
  build/                 # 生成代码、PPTX 渲染图
  qa/report.md           # 三类检查、修复和差异
  output/deck.pptx
```

无需数据库/服务。项目记录用相对路径便于移动；用户回复中的链接使用实际绝对路径。

`slides.yaml` 最小结构示例（填入当前项目真实内容）：

```yaml
slides:
  - id: s01
    revision: 1
    title: "当前页标题"
    message: "本页核心信息"
    content:
      - text: "确认的正文或结论"
        source: "sources.md#src01，p.3"
    presentation: "对比表"
    layout: "上方标题，主体两列对比"
    data: null
    assets: []
    editability:
      native: ["标题", "正文", "对比表"]
      images: []
    accepted_visual: null
```

图表的 data 保留真实类别、系列、数值、单位和来源；架构图记录节点及有向关系。实验结果/结论逐条记录原文定位；计算得出的新数值标为派生值，保存公式和输入定位，不能称为原文数据。素材记录源路径/URL、文件哈希、页码/图表号、截图裁剪范围及使用位置，不把图片可见但未确认的内容写成事实。

`state.json` 至少记录：当前阶段、整体规格版本、每页版本、确认产物路径与版本、用户确认原话、待改页/原因、下一步。生图结果记录真实工具名和输出位置。确认不能只保存在聊天里。

## 变更与确认失效

- 改文字/数字：用户明确要求的局部改动直接落实并校验，需主 agent 新作重大内容取舍时合并展示确认，随后更新 PPT 和检查；用户明确免除某轮确认时记录指令。
- 改布局/局部风格：回到对应页的 HTML 或图片阶段，其他页的批准保留。
- 改受众/目的/范围/整体风格：重审 brief 与受影响大纲/页面，不沿用失效批准。
- 修复 PPT 还原缺陷：保持确认内容与冻结图片不变，直接修复再校验，不为每次修复索取批准。
- 仅批准样张：默认允许扩展、内部校验及重建交付，记录 sample_approved 和 generated_reference，不能写为全套 user_approved；详细模式仍在指定点等待。

保留被替代版本或可恢复副本，避免“最新生成”变成“用户已确认”。用户批准小差异时记录其对应 PPT 版本，不改写原参考图片。
